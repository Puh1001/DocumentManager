**Status:** Pending  
**Priority:** High

## Overview

Add `KpiStatus` enum and `status` field to `KpiRecord` model. Simple additive migration.

## Requirements

### Functional
- Status field tracks KPI completion state
- Three status values: PENDING, IN_PROGRESS, COMPLETED
- Default value: PENDING (for new records)
- Nullable initially (for existing records, updated via data migration)

### Non-Functional
- Migration must be reversible
- No downtime (additive only)
- Existing records default to PENDING

Add after `RowMode` enum (around line 360):

```prisma

  PENDING      // Initial state, no files uploaded
  IN_PROGRESS  // Work started (manual only)
  COMPLETED    // Files uploaded or manually marked complete
}
```

#### 2. Update KpiRecord Model

Add `status` field after `rowMode` (around line 338):

```prisma
model KpiRecord {
  id           String       @id @default(uuid())
  departmentId String       @map("department_id")
  year         Int
  title        String
  target       String
  targetValue  Float?       @map("target_value")
  displayType  DisplayType  @default(PERCENTAGE) @map("display_type")
  rowMode      RowMode?     @map("row_mode")
  status       KpiStatus    @default(PENDING) @map("status")  // NEW FIELD
  createdAt    DateTime     @default(now()) @map("created_at")
  updatedAt    DateTime     @updatedAt @map("updated_at")
  createdBy    String?      @map("created_by")

  department   Department      @relation(fields: [departmentId], references: [id], onDelete: Cascade)
  metrics      KpiMetric[]
  attachments  KpiAttachment[] @relation("KpiRecordAttachments")

  @@unique([departmentId, year, title])
  @@index([departmentId])
  @@index([year])
  @@index([status])  // NEW INDEX for filtering
  @@map("kpi_records")
}
```

If migration fails:

```bash

cd apps/api

# Or manually:
psql -d iso_docs -c "DROP INDEX IF EXISTS kpi_records_status_idx;"
psql -d iso_docs -c "ALTER TABLE kpi_records DROP COLUMN IF EXISTS status;"
psql -d iso_docs -c "DROP TYPE IF EXISTS KpiStatus;"
```
