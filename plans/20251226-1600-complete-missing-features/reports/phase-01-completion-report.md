## Key Features

### Permission Display

- Automatically filters permissions by module name pattern
- Shows permissions in format: `action:module` (e.g., "view:User")
- Displays action badges (view, create, edit, delete, manage)
- Shows count of permissions per module

### Auto-Generation

- When creating a new module, backend automatically generates 5 standard permissions:
  - `view:{Module}`
  - `create:{Module}`
  - `edit:{Module}`
  - `delete:{Module}`
  - `manage:{Module}`

### Security

- Page protected with `PageGuard` component
- Requires `manage:all` permission (admin-only)
- Backend API already protected with `@CheckPolicies({ action: "manage", subject: "all" })`

## Notes

### Module Name Consideration

The page metadata uses `module: "Module"`. This assumes there's a "Module" module in the database. If not, the page will still work but PageGuard might not enforce permissions correctly. Consider:

1. Creating a "Module" module in the database
2. Or using a different module name (e.g., "System" or "Admin")

### Permission Display Logic

Permissions are filtered by matching the pattern `${action}:${moduleName}`. This works for all standard permissions generated by ModuleService.
